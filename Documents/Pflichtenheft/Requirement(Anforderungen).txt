Requirement(Anforderungen)

=====================================================================================================================================
Functional requirements: (Funktionale Anforderungen)
=====================================================================================================================================
-F1: Movement in the VR Environment		
Tested by:                                      Implemented by: M1
The user must be able to move around in the VR environment using their natural body movements.
Additionally they must be able to move longer distances that would not be walkable by teleportation.

-------------------------------------------------------------------------------------------------------------------------------------
-F2: Browsing Interface				
Tested by:                                      Implemented by: M2
The UI needs to have an interface for browsing lectures.
This interface needs to include a search bar and controls for browsing through the folder architecture.

-------------------------------------------------------------------------------------------------------------------------------------
-F3: Lecture Player				
Tested by:                                      Implemented by: M2
The UI needs to have an option for playing lectures.
This lecture player must include basic controls for pausing, skipping ahead and going back as well as enabling and disabling subtitles.
It should display how far in the lecture the user is using a bar.

-------------------------------------------------------------------------------------------------------------------------------------
-F4: Text Document Display			
Tested by:                                      Implemented by: M3
The UI needs to have an option for displaying text documents related to a lecture, such as the full transcript, translations and summaries.

-------------------------------------------------------------------------------------------------------------------------------------
-F5: Virtual Avatar for the Dialogue System	
Tested by:                                      Implemented by: M4
The system must include a virtual avatar that visually represents the AI dialogue system within the VR environment. 

-------------------------------------------------------------------------------------------------------------------------------------
-F6: Text Display for the Dialogue System	
Tested by:                                      Implemented by: M4
The UI must display both user questions and avatar responses as on-screen text to support the dialogue system. 
This may appear as subtitles or in a dialogue box within the VR environment.

-------------------------------------------------------------------------------------------------------------------------------------
-F7: Switching Environments			
Tested by:                                      Implemented by: K1
The program must be able to load different 3D environments in order to switch between them by picking one in the settings. 

-------------------------------------------------------------------------------------------------------------------------------------
-F8: Font Size Adjustment Interface 	
Tested by:                                      Implemented by: K4
The UI must provide a settings interface that allows users to increase or decrease the font size to improve readability in the VR environment. The adjustment should be accessible within the video or general settings menu and allow users to increase or decrease the font size by using '+' and '-' buttons. Changes should be reflected immediately in the VR view and persist throughout the session.
-------------------------------------------------------------------------------------------------------------------------------------
-F9: Continue Watching Feature		        
Tested by:                                      Implemented by: K5
The system must remember the user's last watched position in a lecture and, upon return, the UI must prompt the user whether to resume playback from that point.

-------------------------------------------------------------------------------------------------------------------------------------
-F10: Playback Speed Control                    
Tested by:                                      Implemented by: K6
The UI must provide a setting that allows users to adjust the playback speed of lecture videos. 
The system must support playing videos at different speeds, such as slower or faster than the default.

-------------------------------------------------------------------------------------------------------------------------------------
-F11: Content Interaction Tutorial              
Tested by:                                      Implemented by: K7
The system must provide a tutorial for first-time users that guides them through the core content interaction features. 
The tutorial must demonstrate how to browse and play lecture videos using playback controls (pause, skip, subtitles), how to access text-based materials such as transcripts, translations, and summaries, and how to interact with the virtual avatar to ask questions related to the lecture. 

-------------------------------------------------------------------------------------------------------------------------------------
-F12: Automatic Display Mode Switch             
Tested by:                                      Implemented by: K8
The system must automatically switch between dark mode and light mode based on the user's local sunrise and sunset times.
The mode change should occur without requiring manual user input.

--------------------------------------------------------------------------------------------------------------------------------------
-F13: Offline Mode				
Tested by:                                      Implemented by: K9
The system must allow users to download video content and associated transcripts so that lectures can be accessed without an internet connection.

--------------------------------------------------------------------------------------------------------------------------------------
-F14: Multitasking				
Tested by:                                      Implemented by: K2
The user must be able to open multiple UI windows at once, move them around in 3D and resize them.
These windows include: F2, F3, F4, F6, F9

--------------------------------------------------------------------------------------------------------------------------------------
-F15: Taking notes				
Tested by:                                      Implemented by: K3
The UI must provide a window to take notes while watching lectures and save them locally. 
Notes can include time stamps referencing specific lecture moments. Users must be able to edit and delete their notes at any time.
In addition, users should be able to create general notes that are not linked to a specific lecture.?

--------------------------------------------------------------------------------------------------------------------------------------
-F16: Main Menu
Tested by:					Implements: K2
By pressing the menu button on either of the controllers, a menu should open above the hand on wich the button was pressed.
This menu should be navigable using the control sticks and A button and should include the options: Browse Lectures, Notes, Settings.
Pressing the a button with one of these selected should open a new window of the correlating type.
Pressing the menu button again on either controller should close this menu.

======================================================================================================================================
Non-Functional requirements: (Nicht-funktionale Anforderungen)
======================================================================================================================================

-N1: Multilingual User Interface
The UI should support at least English and German.

--------------------------------------------------------------------------------------------------------------------------------------
-N2: Error Messaging
If any lecture content, subtitle file, or environment asset fails to load, 
the system shall display error message indicating the reason within 5 seconds and provide the user with at least one recovery option (e.g., retry, return to menu), without terminating the application.

--------------------------------------------------------------------------------------------------------------------------------------
-N3: Offline Robustness
All features tagged for offline support (e.g., lecture playback, transcript viewing, note-taking) shall be fully functional when the device has no internet access, as long as the corresponding resources have been downloaded.

--------------------------------------------------------------------------------------------------------------------------------------
-N4: Security & Privacy
All user-generated content, including notes, playback position, and preferences, shall be stored solely on the local device. 
No data is to be transmitted to external servers or cloud services. 
Users can review and delete their data from the system at any time.

--------------------------------------------------------------------------------------------------------------------------------------
-N5: Extensibility
The system architecture shall be extensible so that additional features—such as user accounts, cross-platform support, or voice input—can be added later without major redesign. 
These extensions are not part of the current implementation scope.
